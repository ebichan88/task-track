# 設計上の決定事項

要件定義書「10. 未確定事項・設計時の検討事項」について、初期版（MVP）で採用した方針をまとめる。
いずれも実装を単純に保つことを優先した決定であり、利用状況を見て見直してよい。

| No. | 項目 | 採用した方針 |
|---|---|---|
| 1 | Swing 画面レイアウト | 1ウィンドウ構成。左側にタイマー（計測中作業の表示と開始フォーム）を常時表示し、右側にタブで「作業記録／集計／日次振り返り／マスタ管理／データ出力／バックアップ」を配置する。作業記録の登録・編集・削除はモーダルダイアログで行う。 |
| 2 | DB ファイル保存場所 | `%APPDATA%\TaskTrack\tasktrack.db`（Windows）。`APPDATA` が無い環境では `~/.tasktrack/tasktrack.db`。システムプロパティ `tasktrack.dataDir` で変更できる。同じフォルダのロックファイルで二重起動を防ぐ。 |
| 3 | Windows 起動時の自動起動 | サポートしない（必要なら利用者がスタートアップにショートカットを置く）。 |
| 4 | 異常終了時の複数未終了記録 | 未終了（終了日時が NULL）の記録は部分ユニークインデックスにより DB レベルで同時に1件までに制限しており、通常は複数になり得ない。処理自体は複数件にも対応しており、開始日時の古い順に1件ずつ対応を確認する。 |
| 5 | ショートカットキー | 初期版では実装しない。 |
| 6 | 作業記録の時間重複 | 許可する（警告もしない）。会議中の並行作業などを妨げないため。タイマーによる記録同士は仕組み上重複しない。 |
| 7 | 作業記録削除時のタグ情報 | 外部キーの `ON DELETE CASCADE` により、紐付け（`time_entry_tag`）も同時に削除する。タグマスタ自体は残す。タグを削除した場合も同様に紐付けだけが消える。 |
| 8 | マスタ無効化時の扱い | 無効化したプロジェクト／カテゴリは、新しい作業の選択肢に表示しない。過去の作業記録・集計では名前の後ろに「（無効）」を付けて表示する。無効なマスタを使っている記録を編集するときは、そのマスタを選択肢に残す。マスタの物理削除は行わない。 |
| 9 | 週の開始曜日 | 月曜日。 |
| 10 | 日次集計の境界 | 日本時間（Asia/Tokyo）の 0:00。日付をまたぐ作業記録は日ごとに分割して集計する。PC のタイムゾーン設定には依存しない。 |
| 11 | バックアップ世代管理 | 行わない。バックアップは利用者が保存先とファイル名を指定して作成する（既定名は日時入りなので、同じフォルダに保存すれば世代として残せる）。復元時のみ、直前の DB を `tasktrack.db.pre-restore` に1世代だけ自動退避する。 |
| 12 | CSV 期間指定の境界条件 | 開始日の 0:00（含む）から終了日の翌日 0:00（含まない）まで。いずれも日本時間。つまり開始日・終了日とも「その日全体」を含む。 |
| 13 | segment_id の生成規則 | `{entry_id}_{出力区間の開始時刻}`。開始時刻は UTC の `yyyyMMdd'T'HHmmss'Z'` 形式。例: `…-9f3c_20261115T140000Z`。乱数ではなく決定的な値なので、同じ区間は何度出力しても同じ ID になり、期間を分けて出力した区間同士は別の ID になる。 |

## そのほかの実装上の決定

### データの持ち方

- 日時は UTC のエポック秒（`INTEGER`）で保存し、表示・集計・出力時に日本時間へ変換する。精度は秒。
- ID はすべて UUID（文字列）。
- 計測中の作業は「終了日時が NULL の `time_entry`」として表現する。タイマー専用の状態は別に持たない。
  開始・停止・切り替えはそれぞれ1トランザクションで保存するため、経過時間を定期的に書き込む必要がない。
- `app_state` はキー・バリュー形式で、スキーマバージョン（`schema_version`）と、前回の出力先・バックアップ先フォルダを保持する。
- SQLite は `journal_mode=DELETE`・`synchronous=FULL`・`foreign_keys=ON` で使用する。DB は常に単一ファイルで完結する。

### タイマー

- 「正常終了」はメインウィンドウを閉じる操作を指す。このとき計測中の作業を現在時刻で停止する。
- Windows のシャットダウン・ログオフ・強制終了で終了した場合は未終了記録が残り、次回起動時に対応を確認する。
- 計測中の作業を編集画面で開いた場合、終了日時を入れずに保存すれば計測を継続する。
- PC の時計が巻き戻っていた場合でも、終了日時が開始日時より前にならないよう開始日時に丸める。

### 集計

- 計測中（未終了）の作業は集計に含めない。
- 期間の境界をまたぐ記録は、期間内の部分だけを集計する。
- 件数は「その行（日・週・カテゴリなど）に掛かる作業記録の数」。日付をまたぐ記録は両方の日で1件と数える。

### データ出力

- 計測中（未終了）の作業は出力しない。
- `projects.csv`・`categories.csv`・`tags.csv` は、出力される作業記録から参照されているものだけを出力する
  （「指定した期間に該当するデータのみを出力する」に合わせ、期間と無関係な案件名などを出力しないため）。
- 値はすべてダブルクォートで囲む。NULL は空欄（クォートなし）、空文字は `""` として区別する。
- 数式の無害化: 文字列値の先頭が `=` `+` `-` `@`、タブ、改行（および全角の `＝` `＋` `－` `＠`）の場合、先頭に `'` を付ける。
  DB の値は変更しない。
- 日次振り返りは、全項目が空のものは保存しない（空で保存すると既存の振り返りは削除される）。

### バックアップ・復元

- バックアップは SQLite の `VACUUM INTO` で作成する。トランザクション的に一貫したスナップショットになる。
- 復元前に、バックアップファイルが SQLite として健全か（`PRAGMA integrity_check`）、本アプリの DB か、
  対応可能なスキーマバージョンかを検査する。問題があれば現在のデータには触れない。
- 復元後に DB を開けなかった場合は、退避しておいた直前の DB に自動で戻す。
- 復元した DB に未終了の作業記録が含まれていた場合は、起動時と同じ確認ダイアログを表示する。
